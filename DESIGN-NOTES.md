# Design notes: directions explored, inspiration, and pivots

This is a working trace of the homepage build, kept separate from `DECISIONS.md` (which is Sang's own log, not something Claude fills in). It exists so nothing gets lost before the video and the decision log get written, especially the moments where a direction got built, then overruled or reverted. Sourced from the actual session; nothing here is invented.

## Where things stand right now (as of 2026-09-22, `2bb02a7`, fully pushed)

The rest of this file is a history of how it got here; this section is what's actually live, for anyone (or any new Claude session) picking this up cold.

- **Layout**: fixed-left / scrolling-right, per brittanychiang.com. `.page-shell` (grid, `minmax(26rem, 42rem) 1fr`) → `.side-panel` (sticky left) and `.content-column` (scrolling right: three work sections, about, footer). Collapses to one stacked column under 900px.
- **Sidebar**: real headshot photo (`images/headshot.jpg`) next to the name, a "Currently in Colorado" line, the career trajectory scene, then nav and icon-only contact links (envelope, LinkedIn), plus a separate ambient point-cloud backdrop (`ambient-pointcloud.js`) spanning the whole panel behind everything.
- **Visuals**: two Three.js layers in the sidebar now, deliberately separated to avoid a coordinate-correspondence bug hit earlier this session (see "Career timeline, round two" below). `career-timeline.js` is the boxed, labeled, interactive scene (drag to orbit, no scroll-zoom, gradient tube trajectory, real milestone markers with floating labels). `ambient-pointcloud.js` is a separate, non-interactive, sparser backdrop layer behind the whole sidebar, reviving the spirit of the original (now-deleted) hero point cloud but purely atmospheric.
- **Palette**: cool/technical, deep blue-black ground, steel-blue (`--accent`) + ice-cyan (`--accent-2`, scoped to `#data-science` only) accents. Type: Public Sans (body), Martian Mono (labels/data), Unbounded (the name only).
- **Content**: three work sections, renamed from "Full-Stack + AI Engineering" to plain "Full-Stack Engineering" (Sang doesn't identify as an "AI engineer"), real resume-backed bullets, audited against the actual resume PDF for completeness. The Lockheed Martin "incoming" entry was removed entirely at Sang's request, it no longer appears anywhere (resume section or the 3D timeline's milestones). The Teaching Assistant role moved out of Full-Stack Engineering into the About section, next to education, since it's not full-stack work. Per-section thesis lines (one-sentence framing under each heading) were added, then later removed at Sang's request; the heading's own spacing was adjusted to compensate.
- **Applied Data Science**: interactive PDSI explorer (`drought-explorer.js`, real values from the reimplementation), a real poster image for the cloud-gaming research (downloaded and rendered from the actual Mines repository PDF Sang linked, not just a DOI), and the SPI/SPEI chart converted from a full-bleed white embed to the same boxed thumbnail-link treatment the posters use (a bright, light-background image clashing with the dark theme, same problem the posters already solved). All external citation links use a consistent `↗` external-link marker.
- **About → "beyond the resume"**: three real, small cards. A merged stats.fm + real top-Spotify-artists card (the artists card is populated by `spotify-top.js` reading `spotify-top-artists.json`, a file a scheduled GitHub Action, `.github/workflows/spotify-stats.yml`, regenerates from the real Spotify Web API every 6 hours; no API key ever touches the browser). A real Leaflet map (`travel-map.js`) with Esri's free dark-gray basemap (switched from CARTO after CARTO's anonymous tiles turned out to now require an API key) showing real travel: Seattle, Las Vegas, Japan, and a general Vietnam-area marker, no flight numbers or other sensitive detail, just city + date range, plus the same info duplicated in a plain accessible list below the map. A real concerts-attended card, seven shows in chronological order (Clipse, Colorado Symphony, Martin Garrix, Denzel Curry/Freddie Gibbs/Earl Sweatshirt, Khalid, Don Toliver, Wave to Earth, RL Grime), every date/venue verified via web search and confirmed back with Sang before publishing, including two genuinely nice real coincidences caught during that research: the Wave to Earth Seattle show landed on day one of Sang's actual Seattle trip, and the RL Grime Zouk show landed on day one of the Las Vegas trip.
- **Consistency pass**: nav links, the side-role byline, all three numbered section tags, "Education", "Beyond the Resume", the travel card's "Upcoming" tags, the "Vector Databases" skill tag, and the PDSI explorer label were all lowercase while section headings were Title Case; made consistent. ## Final: fixed-left / scrolling-right layout

Restructured the whole page: `.page-shell` grid, a sticky `.side-panel` (point cloud as a contained backdrop, name, vertical nav with scroll-linked active-section highlighting via `IntersectionObserver`, contact links) on the left, and `.content-column` (all three work sections, about, footer) scrolling on the right. The old JS-injected top nav (`reveal.js`'s `buildNav`) was removed in favor of real, always-present static nav markup, more robust and closer to the course's "verify it actually works" spirit than a script-built one. The per-section side-stat cards from the previous round were removed since the persistent sidebar replaces that job.

## Career timeline: several rebuilds, following direct feedback each time

Built, shown, and rebuilt multiple times in direct response to specific feedback, not guessed at repeatedly:

1. **2D SVG**, a wavy path with flat waypoints for the real dated milestones. Feedback: not SLAM-inspired enough, and wanted real 3D the visitor could move around.
2. **3D Three.js, auto-rotating spheres on a curve**. Feedback: still didn't read as real SLAM output (Sang has looked at many actual SLAM maps), and shouldn't auto-spin, the visitor should control it.
3. **Rebuilt as a SLAM pose graph**: gradient-colored octahedron "keyframe" markers connected by trajectory edges, an ambient point-cloud layer, a ground reference grid, and real `OrbitControls` (drag to orbit, no auto-rotate), the way real SLAM viewers (RTAB-Map, ORB-SLAM3) actually layer these elements. This version stuck.
4. **Follow-up design review** (Sang asked for one, plus to run Impeccable) surfaced two real bugs beyond styling: the markers had no keyboard path at all (a canvas can't expose individual 3D objects to assistive tech), and `OrbitControls` sets `touch-action: none` unconditionally, which would have fought normal one-finger page scroll on phones. Fixed both: a set of visually-hidden buttons mirror the hover/click contract for keyboard users, and touch is now two-finger-only for orbit, one-finger scrolls the page normally.
5. **"Make it feel connected to the hero point cloud"**: matched the timeline's ambient points to the hero's exact color/size/opacity, and added a small cross-module event so dragging the timeline nudges the hero's rotation too.
6. **Tried and reverted**: a literal SVG line drawn from a fixed point on the sidebar to the timeline's live on-screen position, recomputed every frame. Built and technically working (verified the projection math, the visibility gating, the mobile breakpoint), but Sang's read was "doesn't look continuous, looks like two separate things with a line between them." Removed rather than keep iterating blindly on the same idea; the color-match and motion-sync from step 5 were not flagged as bad and were kept.
7. **Tried again, more precisely**: rebuilt the connector so both ends were real points, not one real and one guessed, `pointcloud.js` started publishing its trajectory's actual live (rotating) screen position each frame, and the line drew from that real point to the timeline's real 2023 marker. Sang's response was a different idea entirely: move the timeline itself into the sidebar, replacing the hero point cloud, so there's nothing separate left to connect.
8. **Structural resolution**: `pointcloud.js` retired entirely (deleted); the career timeline moved into `.side-panel-inner`, becoming the sidebar's primary visual; the page-shell grid widened (`minmax(16rem, 26rem)` → `minmax(22rem, 36rem)`) to give it real room, per Sang's explicit "open the left more." The timeline's `IntersectionObserver` visibility-gated render loop (needed when it lived in the scrolling content column) was removed too, the sidebar is always visible, so the loop just runs continuously, the same unconditional approach the old hero used. This is a cleaner resolution than any of the connector attempts: one real, meaningful scene doing double duty as identity visual and career content, instead of one real scene plus one decorative one trying to look related.

## Career timeline, round two: bigger box, a separate ambient layer, and a real coordinate-space bug

After the timeline moved into the sidebar (see the structural resolution above), Sang asked to widen the sidebar, then to make the trajectory box bigger and bring back a point-cloud effect behind it.

- First attempt: made the canvas span the full sidebar panel while trying to keep the floating labels correctly tracking their 3D points. This broke, labels clamped into a small zone that didn't match the now-much-larger canvas produced garbled, clustered labels with no visible correspondence to the actual scene. Root cause: a 3D point's projected screen position is computed against the canvas's own dimensions; clamping that result into an unrelated, differently-sized/positioned box breaks the correspondence, it isn't a bug to patch, it's two incompatible goals (full-panel canvas vs. a labeled box) fighting each other.
- Sang's explicit correction: keep the original floating-label interaction (canvas and labels sharing one bounded box), just fix the label-overlap problem on top of it, don't replace it with something else. Reverted to the boxed approach, added clamping plus simple pairwise decluttering (nudge a label down if it lands too close to one already placed) to `updateLabels()`.
- Resolved "bigger + point cloud" by keeping the two concerns physically separate instead of merging them into one scene: the boxed/labeled trajectory got bigger and more transparent on its own, and a brand-new, much sparser, non-interactive `ambient-pointcloud.js` (reviving the deleted hero pointcloud's aesthetic) was added as a full-panel backdrop behind everything, no shared coordinate space, so the earlier bug structurally can't recur.
- Follow-up polish: camera moved closer, `OrbitControls.enableZoom` set to `false` (drag-to-rotate only, learned from an earlier scroll-trap bug with the same library) so scrolling the page over the box doesn't get hijacked, and the box's solid background swapped for a `color-mix()` translucent one so the ambient layer shows through it.
- Lockheed Martin's "incoming" milestone was removed from `career-timeline.js`'s `MILESTONES` array too, once removed from the resume section, so the 3D scene and the written content stay in sync.

## Real, auto-refreshing data instead of static content: Spotify and a travel map

Sang wanted actual personality on the site, not more static boxes. Two real integrations resulted, both chosen after ruling out fake alternatives:

- **stats.fm has no public API** suitable for embedding (confirmed by checking their embed page, developer docs, and a community thread about "private API access" gating), so a genuinely live embed wasn't possible without infrastructure this static site doesn't have.
- **Spotify's own Web API does work**, Sang supplied a working sample token from Spotify's own docs playground, verified live (it returned Sang's real top tracks). Since that token expires in about an hour and must never be committed, the durable version is a scheduled GitHub Action (`.github/workflows/spotify-stats.yml`) holding a refresh token as a repo secret, refreshing an access token, pulling real top artists, and committing the result as `spotify-top-artists.json`. The OAuth authorization-code exchange (getting the refresh token) was done together: Sang clicked a real authorization URL and pasted back the redirected code, Claude did the token exchange and `gh secret set` calls, and the temp file holding the token response was deleted immediately after. A real bug surfaced on the first run: the commit step used `git diff --quiet`, which only detects changes to already-tracked files, so it silently skipped committing the brand-new JSON file. Fixed by staging first, then checking `git diff --cached --quiet`, re-ran, and it worked.
- **The travel section became a real Leaflet map** instead of staying plain text, with an explicit privacy line drawn first: flight numbers and precise itineraries were declined even though Sang offered them, since publishing exact travel dates/flight details on a public site is a real safety consideration, not just a style choice. CARTO's free anonymous basemap tiles, the original plan, turned out to require an API key now (a real policy change caught only by testing in-browser, `curl` alone didn't catch it since it was serving stale cached tiles), swapped for Esri's free, keyless dark-gray canvas basemap instead, verified with a fresh (non-cached) fetch before committing to it.
- Both the Spotify card and the map got a round of "make it bigger" and layout fixes: `.personal-grid` switched from a content-sized flex row to a responsive two-column grid so the cards stay equal width instead of one dominating.

## Picking this back up on a different computer

Everything in this repo is fully pushed (see "Where things stand right now" above for the exact commit). One thing is NOT in this repo and won't come along with a clone: the [Impeccable](https://github.com/pbakaus/impeccable) skill is installed globally (`~/.claude`) on the machine this was built on, not tracked by git at all.
